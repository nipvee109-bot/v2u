### Rules every blueprint follows
- The learner acts first; the explanation names what they just saw.
- One concept · one meaningful action · one immediate result; controls appear only when needed.
- Wrong actions produce a **visible consequence** (tilts, stops, mismatches), then a one-line reason.
- Interactions report only attempts / solved / hints / reveals / responses / time. **Mastery, review,
  Diagnostic level and Next Step stay with the existing Learning Core.**
- "Fun without rewards" check: if XP/points were removed, would the action still be satisfying? Answered per lesson.
- Mobile line format: **390** (phone) · **768** (tablet) · **1440** (desktop). A11y line: keyboard · touch · focus · non-colour · reduced motion · text equivalent.

reading, not doing. Every lesson's verified practice (`verify` answers) already exists — the target is to
replace self-rated steps with **checked attempts inside the lesson's own mechanic**. Listed in each gap below.

## A1. Mathematics

### math-alg-linear-eq
**SUBJECT:** math · **TOPIC:** math-algebra · **SKILLS:** skill-math-solve-linear, skill-math-check-solution

1. **Core understanding:** สมการคือสองข้างที่ “หนักเท่ากัน”; ทุกการกระทำต้องทำกับทั้งสองข้าง และคำตอบตรวจได้ด้วยการแทนกลับ
2. **Why it is hard:** “ย้ายข้างเปลี่ยนเครื่องหมาย” ถูกท่องเป็นกฎลอย ๆ จึงลืมเครื่องหมาย กระจายวงเล็บไม่ครบ และไม่เคยตรวจคำตอบ
3. **Make visible:** ความสมดุล (invariant) และการ “ยกเลิก” พจน์ — เห็นว่า −3 ทั้งสองข้างทำให้ +3 หายไป ไม่ใช่ “ย้ายไป”
4. **Learner action:** ลากก้อนน้ำหนัก/กล่อง x ออกจากตาชั่ง, กดแบ่งกลุ่ม (หาร), แกะวงเล็บเป็นก้อนย่อย
5. **Immediate consequence:** ตาชั่งยังตรงหรือเอียงทันที และบรรทัดสมการเขียนตัวเองตามการกระทำ
6. **Best mechanic:** *ตาชั่งสองแขนเป็นพื้นที่ทำงานหลักของทั้งบท* — `4(x + 3) = 2x + 18`: แตะวงเล็บ → แตกเป็น 4 กล่อง x กับ 4 ก้อน 3; ลากกล่อง x 2 กล่องออก “ทั้งสองข้าง” (ลากจากฝั่งหนึ่ง อีกฝั่งหายพร้อมกันเมื่อเปิด “ทำทั้งสองข้าง”) → `2x + 12 = 18`; ลากก้อน 12 ออก → `2x = 6`; แบ่งตาชั่งเป็น 2 กลุ่มเท่ากัน → `x = 3`; ปุ่ม “แทนกลับ” วางก้อน 3 ลงในทุกกล่อง x ของสมการเดิมให้ชั่งดูว่าตรงจริง
7. **Why it teaches:** การ “รักษาสมดุล” คือกฎทั้งหมดของบท — ลากออกข้างเดียวแล้วตาชั่งเอียงคือภาพของการผิด ไม่ใช่คำว่า “ผิด”
8. **Beginner scaffold:** เริ่ม `x + 3 = 7` ที่ตาชั่งล็อก “ทำทั้งสองข้าง” ไว้ให้; มีปุ่มเดียวที่ทำได้
9. **Support removal:** ปลดล็อกให้ลากข้างเดียวได้ (เพื่อให้เห็นว่าเอียง) → x สองข้าง → วงเล็บ → เศษส่วน `x/3 + x/6 = 5` (คูณทั้งตาชั่งด้วย 6) → สุดท้ายเขียนสมการเองโดยไม่มีตาชั่ง แล้วใช้ “แทนกลับ” ตรวจ
10. **Failure experience:** ลากออกข้างเดียว → ตาชั่งเอียง + สมการแสดง `x = 9 + 5` ขีดแดงว่า “สองข้างไม่เท่ากันแล้ว”; กระจายวงเล็บไม่ครบ → กล่องที่เหลือในวงเล็บยังอยู่ ตาชั่งไม่ตรงตอนแทนกลับ
11. **Feedback:** “ข้างซ้ายเบาลง 3 แต่ข้างขวายังเท่าเดิม — เอาออกเท่ากันทั้งสองข้าง”
12. **Challenge / fun:** ปริศนา “ทำให้ x อยู่คนเดียวด้วยจำนวนท่าน้อยที่สุด”; ความพอใจจากตาชั่งที่ตรงพอดี · *Fun without rewards:* **ใช่** — การทำให้ตาชั่งสมดุลเองน่าพอใจ
13. **Independent application:** แก้ `x/2 − (x − 1)/3 = 2` โดยเขียนขั้นเอง แล้วตรวจด้วยการแทนกลับ (ไม่มีตาชั่ง)
14. **Proof of understanding:** แก้สมการใหม่ที่มี x สองข้าง + วงเล็บ และ **ทายได้ก่อนลาก** ว่าการกระทำไหนจะทำให้เอียง
15. **Evidence:** attempts/solved ต่อสมการ, จำนวนครั้งที่ตาชั่งเอียง (response), hint, reveal, คำตอบที่แทนกลับ
16. **Game decision:** OPTIONAL_GAME
17. **Game reason:** ด่านตาชั่ง (Balance Puzzle) — การกระทำในเกม = การรักษาสมดุลจริง แต่บทเรียนหลักสอนครบโดยไม่ต้องมีเกม
18. **Current implementation:** KEEP_BUT_IMPROVE — มีตาชั่งแล้วแต่ใช้กับสมการเดียวด้วยปุ่ม 4 ปุ่ม ส่วนที่เหลือเป็น typed/choice
19. **Priority:** P1
20. **Acceptance test:** ผู้เรียนที่ไม่เคยแก้สมการ ทายถูกก่อนลากว่า “เอา 3 ออกข้างเดียว” จะทำให้ตาชั่งเอียง และแก้ `2x + 5 = x + 9` ได้โดยไม่พูดคำว่า “ย้ายข้าง”
- **Mobile:** 390 ตาชั่งเต็มความกว้าง ปุ่มการกระทำเป็นแถบล่าง (แตะแทนลาก) · 768 ตาชั่ง + บรรทัดสมการคู่กัน · 1440 ตาชั่ง | ประวัติขั้นสมการด้านข้าง
- **A11y:** ทุกการลากมีปุ่ม “เอาออกทั้งสองข้าง” ทางคีย์บอร์ด; สถานะ “สมดุล/เอียง” เป็นข้อความ; ลดการเคลื่อนไหว = เอียงทันทีไม่มีแอนิเมชัน; ข้อความ alt บอกสิ่งที่อยู่บนแต่ละข้าง

### math-alg-linear-system
**SUBJECT:** math · **TOPIC:** math-algebra · **SKILLS:** skill-math-linear-system, skill-math-word-problem

1. **Core understanding:** คำตอบของระบบคือคู่ (x, y) ที่ทำให้ *ทุก* สมการจริงพร้อมกัน; แทนค่า/กำจัดตัวแปรคือการลดสองตัวแปรให้เหลือหนึ่ง; โจทย์ปัญหาคือความสัมพันธ์สองชุด
2. **Why it is hard:** ผู้เรียนหาได้ตัวเดียวแล้วหยุด, ตรวจกับสมการเดียว, และ “แปลงโจทย์เป็นสมการ” มองไม่เห็นว่าอะไรคือ x/y
3. **Make visible:** ความเป็นจริง (truth) ของแต่ละสมการแยกกัน + การแทนที่ (substitution as replacement) + ความสัมพันธ์สองชุดในโจทย์
4. **Learner action:** ปรับ x, y แล้วดูไฟของแต่ละสมการ; ลาก “x = y + 2” ไปแทนที่กล่อง x; ลากจำนวนจากเรื่องราวลงช่องสมการ
5. **Immediate consequence:** ไฟสมการ ✓/✗ เปลี่ยนทันที; เมื่อแทนที่ สมการที่สองเหลือตัวแปรเดียวต่อหน้า; ตารางเรื่องราวเติมแล้วสมการประกอบตัวเอง
6. **Best mechanic:** สามช่วงในบทเดียว — (a) *ไฟความจริงสองดวง*: ตารางคู่ (x, y) ที่ผู้เรียนลองเอง แต่ละแถวมีไฟของสมการ 1 และ 2 แยกกัน (มีอยู่แล้ว) (b) *เครื่องแทนที่*: แตะ `x − y = 2` → จัดรูปเป็นป้าย `x = y + 2` → ลากป้ายไปทับทุก x ใน `3x + 2y = 16` → เห็น `3(y + 2) + 2y = 16` แล้วแก้ด้วยตาชั่งจากบทก่อน (c) *ตารางแปลงเรื่องราว*: โจทย์ตั๋ว 20 ใบ เงินรวม → ผู้เรียนลาก “จำนวนใบ” กับ “จำนวนเงิน” ลงสองแถว (ผู้ใหญ่/เด็ก) ระบบประกอบ `x + y = 20` และ `60x + 40y = …`
7. **Why it teaches:** ไฟสองดวงทำให้ “พร้อมกัน” เป็นสิ่งที่เห็น; การแทนที่แบบลากป้ายคือความหมายของ “แทนค่า” ตรงตัว; ตารางเรื่องราวแยก “นับจำนวน” กับ “นับเงิน” ซึ่งเป็นจุดที่คนสับสน
8. **Beginner scaffold:** ระบบที่คำตอบเป็นจำนวนเต็มเล็ก, ตารางคู่เริ่มมีแถวตัวอย่าง 2 แถว
9. **Support removal:** ไฟเปิด → ซ่อนไฟ (ต้องแทนค่าเอง) → เครื่องแทนที่แบบแนะนำ → ผู้เรียนเลือกเองว่าจะแทนหรือกำจัด → โจทย์เรื่องราวใหม่ที่ไม่มีตารางให้
10. **Failure experience:** หยุดที่ y = 2 → ระบบถามคู่ (x, y) และไฟสมการ 1 ยังดับ; ลบสมการไม่ครบพจน์ → พจน์ที่ค้างยังเรืองแสง
11. **Feedback:** “คู่นี้จริงกับสมการที่ 2 แต่สมการที่ 1 ยังไม่จริง — คำตอบของระบบต้องจริงทั้งคู่”
12. **Challenge / fun:** นักสืบหาคู่ที่ “ทำให้ไฟทั้งสองติด” ด้วยเบาะแสน้อยที่สุด · *Fun without rewards:* **ใช่** — การทำให้ไฟสองดวงติดพร้อมกันเป็นการค้นพบ
13. **Independent application:** `2x + 3y = 12, 3x + 2y = 13` และโจทย์ผลรวม/ผลต่าง (50/14) โดยตั้งสมการเอง
14. **Proof of understanding:** อธิบาย (เลือก) ว่าทำไมคู่หนึ่ง “ไม่ใช่คำตอบ” จากไฟ และตั้งสมการจากโจทย์ใหม่ได้ถูก
15. **Evidence:** attempts/solved ต่อระบบ, จำนวนคู่ที่ลอง, การใช้เครื่องแทนที่แบบนำทาง vs อิสระ, hint, reveal
16. **Game decision:** NO_GAME_NEEDED
17. **Game reason:** ไฟความจริงกับตารางเรื่องราวให้ความท้าทายในตัวแล้ว เกมจะซ้ำ
18. **Current implementation:** REDESIGN — มี pair-check ดี แต่ทักษะ word-problem ไม่มีกลไกเลย และท้ายบทเป็น self-reveal 5 ขั้น
19. **Priority:** P0
20. **Acceptance test:** ผู้เรียนเลือกได้ว่าคู่ใดเป็นคำตอบของระบบโดยเหตุผลว่า “ต้องจริงทั้งสองสมการ” และตั้งระบบสมการจากโจทย์ตั๋วใหม่ได้เอง
- **Mobile:** 390 ไฟสมการซ้อนแนวตั้ง ตารางคู่เลื่อนในกรอบตัวเอง · 768 ตาราง | ไฟ · 1440 ตาราง | เครื่องแทนที่ | สมการ
- **A11y:** ไฟมีข้อความ “จริง/เท็จ” ไม่ใช้สีอย่างเดียว; ลากป้ายแทนที่มีปุ่ม “แทน x ด้วย y + 2”; ตารางเป็น `<table>` จริง

### math-alg-linear-ineq
**SUBJECT:** math · **TOPIC:** math-algebra · **SKILLS:** skill-math-solve-inequality

1. **Core understanding:** อสมการมีคำตอบเป็น “ช่วง”; คูณ/หารด้วยลบสลับลำดับ จึงต้องกลับทิศ; วงเล็บ/จุดปลายบอกว่ารวมขอบหรือไม่
2. **Why it is hard:** “กลับทิศเมื่อคูณลบ” ถูกท่อง จึงกลับผิดที่ (ตอนย้ายข้าง) และเขียนช่วงผิด
3. **Make visible:** ลำดับบนเส้นจำนวน (การสะท้อนรอบ 0) และ *เซตคำตอบ* เป็นพื้นที่แรเงา
4. **Learner action:** ทายก่อน → เลื่อนตัวคูณ c (มีอยู่แล้ว); ลากหมุดทดสอบบนเส้นจำนวน; สลับจุดปลายเปิด/ปิด
5. **Immediate consequence:** จุดสองจุดสลับข้างเมื่อ c < 0; หมุดทดสอบเปลี่ยนสีเป็น “จริง/เท็จ” และพื้นที่แรเงาเติมตามค่าที่ทำให้จริง
6. **Best mechanic:** *เส้นจำนวน + หมุดทดสอบ* — หลังแก้ได้ `x < 5` ผู้เรียนลากหมุดไปที่ 4, 5, 6 ดูว่าอสมการเดิมจริงหรือเท็จ แล้ววาดช่วงด้วยการลากขอบแรเงาและเลือกจุดปลายเปิด/ปิด; ระบบเขียน `(−∞, 5)` ตามที่วาด
7. **Why it teaches:** “ช่วง” กลายเป็นสิ่งที่ผู้เรียนสร้างจากการทดลองค่าจริง; การกลับทิศมาจากการเห็นจุดสลับลำดับ
8. **Beginner scaffold:** ทดสอบค่าบนเส้นที่มีป้ายจำนวนเต็ม, จุดปลายมีคำว่า “รวม/ไม่รวม”
9. **Support removal:** เส้นมีหมุดแนะนำ → ผู้เรียนเลือกจุดทดสอบเอง → เขียนช่วงเองโดยไม่วาด
10. **Failure experience:** กลับทิศผิดที่ → หมุดทดสอบในพื้นที่แรเงาให้ผล “เท็จ” ต่อหน้า
11. **Feedback:** “ลองแทน x = 6 ในอสมการเดิม: เป็นเท็จ แต่ 6 อยู่ในพื้นที่ที่คุณแรเงา”
12. **Challenge / fun:** หาจุดที่ “เกือบใช่” (ขอบ) ให้ได้ · *Fun without rewards:* **ใช่** — การทดลองค่าที่ขอบน่าสงสัย
13. **Independent application:** `(x + 1)/2 > x − 3` และ `3(2 − x) ≥ 2x − 9` พร้อมเขียนช่วง
14. **Proof of understanding:** ทายถูกว่าค่าขอบเป็นคำตอบหรือไม่ และกลับทิศเฉพาะเมื่อคูณ/หารด้วยลบ
15. **Evidence:** ผลทาย (response), attempts/solved, จุดทดสอบที่ใช้, hint, reveal
16. **Game decision:** NO_GAME_NEEDED
17. **Game reason:** การทดสอบค่าขอบเป็นความท้าทายพอแล้ว
18. **Current implementation:** KEEP_BUT_IMPROVE — number-line ทาย→สังเกตดีมาก แต่เซตคำตอบ/วงเล็บยังเป็นข้อความ และท้ายบทเป็น self-reveal
19. **Priority:** P1
20. **Acceptance test:** ผู้เรียนบอกได้ก่อนคำนวณว่า x = 5 เป็นคำตอบของ `x ≤ 5` แต่ไม่ใช่ของ `x < 5` และเขียนช่วงถูก
- **Mobile:** 390 เส้นจำนวนเต็มความกว้าง หมุดใหญ่ 44px · 768/1440 เส้นจำนวน + สมการคู่กัน
- **A11y:** หมุดเลื่อนด้วยลูกศรซ้าย/ขวา; ผล “จริง/เท็จ” เป็นข้อความ; จุดปลายใช้วงกลมทึบ/โปร่ง + คำว่า “รวม/ไม่รวม”

### math-alg-exponents
**SUBJECT:** math · **TOPIC:** math-algebra · **SKILLS:** skill-math-exponent-laws

1. **Core understanding:** aⁿ คือการคูณ a ซ้ำ n ตัว; กฎทั้งหมดมาจากการนับตัวคูณ; a⁰ = 1 และ a⁻ⁿ = 1/aⁿ มาจากรูปแบบการหาร; รากคือเลขชี้กำลังเศษส่วน
2. **Why it is hard:** กฎถูกท่องเป็นสูตร (2³·2² = 4⁶), a⁰ = 1 ดูไม่มีเหตุผล, 2⁻³ ถูกคิดว่าเป็นค่าลบ
3. **Make visible:** จำนวนตัวคูณ (quantity) และรูปแบบ “หารด้วยฐานทีละขั้น”
4. **Learner action:** ปรับ m, n แล้วนับก้อน (มีอยู่แล้ว); กด “ลงหนึ่งขั้น” บนบันได 2³ → 2² → 2¹ → 2⁰ → 2⁻¹
5. **Immediate consequence:** ก้อนเพิ่ม/ตัดคู่ทันที; บนบันไดค่าหารครึ่งทุกขั้น (8, 4, 2, 1, ½) ต่อหน้า
6. **Best mechanic:** *ก้อนตัวคูณ + บันไดหารครึ่ง* — ช่วงแรกนับก้อน (คูณ/หาร) ช่วงสองผู้เรียนเดินลงบันไดเอง ทายค่าขั้นถัดไปก่อนกด: เมื่อถึง 2⁰ เห็นว่าเป็น 1 (ไม่ใช่ 0) และ 2⁻¹ เป็น ½ (ไม่ใช่ −2); ช่วงสามแบ่ง 8 ก้อนเป็น 3 กลุ่มเท่ากันสำหรับราก
7. **Why it teaches:** กฎไม่ต้องจำเพราะผู้เรียน “ผลิต” กฎเองจากการนับและรูปแบบ
8. **Beginner scaffold:** ฐาน 2 เท่านั้น เลขชี้กำลังเล็ก
9. **Support removal:** ก้อน → ซ่อนก้อน (นับในใจ) → ฐานเป็นตัวแปร x → นิพจน์ผสม `(x³)² · x⁻⁴`
10. **Failure experience:** ตอบ 4⁶ → แสดงก้อน 2 จำนวน 5 ตัวเทียบกับก้อน 4 จำนวน 6 ตัว (ขนาดต่างกันชัด)
11. **Feedback:** “นับตัว 2 ในแถวได้ 5 ตัว — ฐานยังเป็น 2 เลขชี้กำลังคือจำนวนตัว”
12. **Challenge / fun:** ทายค่าบนบันไดก่อนกด แล้วเห็นว่าถูก · *Fun without rewards:* **ใช่** — “อ้อ มันหารครึ่งเลย” เป็นการค้นพบ
13. **Independent application:** `8^(−2/3)` และ `(x³)² · x⁻⁴`
14. **Proof of understanding:** อธิบาย (เลือกเหตุผล) ว่าทำไม 5⁰ = 1 โดยอ้างรูปแบบ ไม่ใช่ “เพราะกฎบอก”
15. **Evidence:** responses บนบันได (ทายถูก/ผิด), attempts/solved, hint, reveal
16. **Game decision:** NO_GAME_NEEDED
17. **Game reason:** การนับและบันไดสั้นและพอใจในตัว
18. **Current implementation:** KEEP_BUT_IMPROVE — ก้อนตัวคูณดี แต่เลขชี้กำลังศูนย์/ลบ/รากยังเป็นข้อความ
19. **Priority:** P1
20. **Acceptance test:** ผู้เรียนทายได้ว่า 3⁰ = 1 และ 2⁻² = ¼ พร้อมเหตุผลจากรูปแบบหาร
- **Mobile:** 390 ก้อนห่อบรรทัด บันไดแนวตั้ง · 768/1440 ก้อน | บันได คู่กัน
- **A11y:** ก้อนมีข้อความ “2 คูณกัน 5 ตัว”; ปุ่มบันไดใช้คีย์บอร์ดได้; ไม่มีแอนิเมชันที่จำเป็น

### math-fn-linear
**SUBJECT:** math · **TOPIC:** math-functions · **SKILLS:** skill-math-slope, skill-math-graph-reading

1. **Core understanding:** m คือ “x เพิ่ม 1 แล้ว y เปลี่ยนเท่าไร”, c คือค่า y เมื่อ x = 0; กราฟในโจทย์จริงอ่านเป็นความหมาย (ค่าเริ่มต้น + อัตรา)
2. **Why it is hard:** m กับ c เป็นตัวอักษรในสูตร ไม่เชื่อมกับรูปเส้น; อ่านกราฟบริบทไม่ออก
3. **Make visible:** ความสัมพันธ์ (สูตร ↔ เส้น ↔ ความหมาย) และสามเหลี่ยมความชัน
4. **Learner action:** เลื่อน m, c (มีอยู่แล้ว); ในบริบทค่าบริการ ลากหมุดระยะทาง x บนกราฟ
5. **Immediate consequence:** เส้นเปลี่ยนพร้อมสูตร; หมุดบอก “8 กม. = 99 บาท” และสามเหลี่ยม “+1 กม. = +8 บาท”
6. **Best mechanic:** *สูตร ↔ เส้น ↔ เรื่องจริง* — ช่วงหนึ่งให้เส้นผ่านสองจุดโจทย์ (มีอยู่) ช่วงสองกราฟค่าบริการ `y = 8x + 35`: ผู้เรียนลากหมุด x แล้วอ่านราคา, ทายว่าถ้าค่าเริ่มต้นเปลี่ยนเป็น 40 เส้นจะเลื่อนขึ้นหรือชันขึ้น แล้วเลื่อน c ดู
7. **Why it teaches:** เชื่อมสัญลักษณ์กับภาพและกับความหมายในชีวิตจริงในการกระทำเดียว
8. **Beginner scaffold:** m เป็นจำนวนเต็ม สามเหลี่ยม “ไป 1 ขึ้น m” แสดงตลอด
9. **Support removal:** ซ่อนสามเหลี่ยม → ความชันเศษส่วน → หาเส้นจากสองจุดด้วยการคำนวณเอง
10. **Failure experience:** สลับลำดับการลบ → เส้นที่ได้ชันผิดทิศต่อหน้า ไม่ผ่านจุด
11. **Feedback:** “เส้นของคุณผ่าน (1, 3) แต่ลงเมื่อไปทางขวา — y₂ − y₁ กับ x₂ − x₁ ต้องลบลำดับเดียวกัน”
12. **Challenge / fun:** เกมเล็งเส้นให้ผ่านเป้าทุกจุด · *Fun without rewards:* **ใช่** — การเล็งให้ผ่านจุดพอดีน่าพอใจ
13. **Independent application:** สมการผ่าน (−2, 1) ความชัน ½; ถังน้ำ 50 ลิตรไหลออก 2 ลิตร/นาที
14. **Proof of understanding:** อ่านความหมายของ m และ c ในบริบทใหม่ที่ไม่เคยเห็น
15. **Evidence:** attempts/solved, responses ของการทาย, hint, reveal
16. **Game decision:** OPTIONAL_GAME
17. **Game reason:** “เล็งเส้นผ่านเป้า” — การปรับ m, c คือการเรียนเอง แต่บทหลักครบโดยไม่ต้องมีเกม
18. **Current implementation:** KEEP_BUT_IMPROVE (เล็ก) — line-graph ดีแล้ว ขาดช่วงอ่านกราฟบริบท (ทักษะ graph-reading)
19. **Priority:** P2
20. **Acceptance test:** ผู้เรียนเห็นกราฟบริบทใหม่แล้วบอกได้ว่าเส้นตัดแกน y หมายถึงอะไรในเรื่องนั้น
- **Mobile:** 390 แถบเลื่อนเหนือกราฟ กราฟเต็มกว้าง · 768/1440 แถบเลื่อน | กราฟ
- **A11y:** แถบเลื่อนเป็น `<input type=range>` มีป้าย; สถานะ “ผ่านจุด ✓” เป็นข้อความ; สรุปเส้นเป็นข้อความ

### math-trig-ratios
**SUBJECT:** math · **TOPIC:** math-trigonometry · **SKILLS:** skill-math-trig-ratio, skill-math-special-angles

1. **Core understanding:** ข้าม/ชิดขึ้นกับมุมที่พิจารณา; อัตราส่วนขึ้นกับ *มุม* ไม่ใช่ขนาดสามเหลี่ยม; มุมพิเศษมีค่าคงที่
2. **Why it is hard:** ติดป้ายจากตำแหน่ง (ด้านล่าง = ชิด) แทนที่จะดูจากมุม; sin 30/60 สลับกันเพราะท่องตาราง
3. **Make visible:** ด้านที่ “แตะ” มุม vs “ตรงข้าม” มุม; อัตราส่วนคงที่เมื่อย่อ/ขยาย
4. **Learner action:** ลากมุม θ ไปอีกมุมแหลม; ติดป้ายด้าน; ลากมุมยอดเพื่อขยายสามเหลี่ยม
5. **Immediate consequence:** ป้ายข้าม/ชิดสลับเมื่อย้าย θ; ตัวเลขด้านเปลี่ยนแต่ค่า sin θ คงที่
6. **Best mechanic:** *สามเหลี่ยมยืดได้ + θ ย้ายได้* — ผู้เรียนติดป้าย (มีอยู่) แล้ว **ย้าย θ ไปมุมบน** และติดป้ายใหม่ (ฉากไม่เปลี่ยน ข้าม/ชิดสลับ); จากนั้นลากยืดสามเหลี่ยม 30° ให้ใหญ่ขึ้น เห็นด้าน 1:2 ยังคง → sin 30° = ½ ทุกขนาด
7. **Why it teaches:** จุดพลาดอันดับหนึ่ง (ติดป้ายจากตำแหน่ง) ถูกท้าทายโดยตรง; อัตราส่วนคงที่อธิบายว่าทำไมมีตารางค่ามุมพิเศษ
8. **Beginner scaffold:** θ อยู่ตำแหน่งเดียว ติดป้าย “ฉาก” ให้ก่อน
9. **Support removal:** ย้าย θ เอง → ไม่มีป้ายช่วย → หาด้านที่ไม่รู้ด้วยอัตราส่วนที่เลือกเอง
10. **Failure experience:** ติดป้ายผิด → ด้านที่ติดป้ายเรืองแสงพร้อมเส้นจากมุม θ แสดงว่า “แตะ” หรือไม่
11. **Feedback:** “ด้านนี้แตะมุม θ จึงเป็น ‘ชิด’ — ‘ข้าม’ คือด้านที่ไม่แตะ θ เลย”
12. **Challenge / fun:** ยืดสามเหลี่ยมแล้วตัวเลขเปลี่ยนแต่อัตราส่วนไม่เปลี่ยน — ความประหลาดใจ · *Fun without rewards:* **ใช่**
13. **Independent application:** ข้าม 9 ชิด 9√3 หา θ; มุม 45° ชิด 5 หาฉาก
14. **Proof of understanding:** ติดป้ายถูกเมื่อ θ อยู่ตำแหน่งที่ไม่เคยเห็น และเลือกอัตราส่วนจากด้านที่รู้
15. **Evidence:** attempts/solved การติดป้าย (สองตำแหน่ง θ), responses, hint, reveal
16. **Game decision:** NO_GAME_NEEDED
17. **Game reason:** การยืดสามเหลี่ยมเป็นการทดลองที่พอใจในตัว
18. **Current implementation:** KEEP_BUT_IMPROVE — มีการติดป้ายแต่ θ อยู่ที่เดิมเสมอ จึงไม่ทดสอบจุดพลาดหลัก
19. **Priority:** P1
20. **Acceptance test:** เมื่อ θ ย้ายไปอีกมุม ผู้เรียนติดป้ายข้าม/ชิดใหม่ได้ถูกโดยไม่ดูคำใบ้
- **Mobile:** 390 สามเหลี่ยมเต็มกว้าง ปุ่มป้ายใต้รูป · 768/1440 รูป | ปุ่มป้าย
- **A11y:** มุมย้ายด้วยปุ่ม “θ ไปมุมบน/ล่าง”; ด้านมีชื่อข้อความ; การยืดมีแถบเลื่อนแทนลาก

### prog-py-variables

12. **Challenge / fun:** ทายก่อนเห็น แล้วเจอ 4.0 ที่ไม่คาด · *Fun without rewards:* **ใช่** (เซอร์ไพรส์ที่อธิบายได้)
13. **Independent application:** โค้ดที่ผสม `**` กับ `*` และการแปลงชนิด — บอกผลเอง

18. **Current implementation:** KEEP_BUT_IMPROVE (เล็ก) — memory trace ดีแล้ว ขาดการทายชนิดก่อนเห็นและ what-if

### prog-py-io
**SUBJECT:** programming · **TOPIC:** prog-python-basics · **SKILLS:** skill-prog-io

1. **Core understanding:** โปรแกรม “หยุดรอ” ผู้ใช้ที่ `input()` และสิ่งที่ได้เป็น str เสมอ; ต้องแปลงก่อนคำนวณ; f-string ประกอบข้อความจากค่า

6. **Best mechanic:** *คอนโซลจำลองที่ผู้เรียนเป็นผู้ใช้* — โปรแกรมเดินถึง `input("อายุ: ")` แล้ว **หยุดกระพริบรอ**; ผู้เรียนพิมพ์ 16 → เห็นกล่อง `age = "16" (str)`; บรรทัด `age + 1` ล้มด้วย TypeError จริง; ผู้เรียนแก้เป็น `int(input(...))` (เลือกจากตัวเลือก) แล้วรันใหม่ด้วยค่าเดิม
7. **Why it teaches:** “input ได้ str” เห็นได้จากค่าที่ผู้เรียนพิมพ์เองกลายเป็นสตริง
8. **Beginner scaffold:** โปรแกรมทักทายชื่อ (ไม่มีการคำนวณ) ก่อน
9. **Support removal:** ค่าให้เลือก → พิมพ์เอง → ทายผลก่อนพิมพ์ → อ่านโปรแกรมแล้วบอกผลสำหรับค่าที่กำหนดโดยไม่มีคอนโซล
10. **Failure experience:** ลืมตัว f → ผลลัพธ์แสดง `{name}` ตรง ๆ ในคอนโซล
11. **Feedback:** “ค่าที่รับมาคือข้อความ "16" — ต้อง int() ก่อนจึงบวกได้”
12. **Challenge / fun:** ลองพิมพ์ค่าแปลก ๆ (เช่น ชื่อยาว ๆ ทศนิยม) จากชุดที่เตรียมไว้แล้วดูโปรแกรมตอบ · *Fun without rewards:* **ใช่** — การได้ “คุย” กับโปรแกรม
13. **Independent application:** ผู้ใช้พิมพ์ 7 แล้วโปรแกรมแสดงอะไร (บอกเองก่อนรัน)
14. **Proof of understanding:** ชี้ได้ว่าบรรทัดไหนจะล้มกับค่าที่พิมพ์ และแก้ด้วยการแปลงชนิด

### prog-ctrl-loops
**SUBJECT:** programming · **TOPIC:** prog-control-flow · **SKILLS:** skill-prog-loops, skill-prog-trace

1. **Core understanding:** ลูปคือการทำบล็อกเดิมซ้ำโดยตัวแปรเปลี่ยนทุกรอบ; `range(a, b)` ไม่รวม b; ตัวสะสมต้องตั้งค่าก่อนลูป; while หยุดเมื่อเงื่อนไขเท็จ
2. **Why it is hard:** จำนวนรอบมองไม่เห็น; การสะสมเกิดในหัว; infinite loop ไม่มีภาพ
3. **Make visible:** จำนวนรอบ (timing/repetition) + ค่าที่สะสม (state over time)
4. **Learner action:** ทายผลรวมก่อน เดินลูปทีละรอบ (มีอยู่); **เปลี่ยนปลาย range** แล้วนับรอบใหม่; ย้ายบรรทัด `total = 0` เข้า/ออกลูป
5. **Immediate consequence:** แถบรอบ (รอบที่ 1, 2, 3…) เติมทีละช่อง, ค่า i และ total ในตาราง; ย้ายตัวสะสมเข้าลูป → total รีเซ็ตทุกรอบต่อหน้า
6. **Best mechanic:** *ตารางรอบ (iteration ledger) + what-if ขอบเขต* — ทุกครั้งที่บล็อกทำงาน ตารางเพิ่มหนึ่งแถว `i | total`; ผู้เรียนเลือก `range(1, 5)` / `range(1, 6)` (trace ไว้ล่วงหน้า) แล้วนับแถว; while แสดงการตรวจเงื่อนไขก่อนทุกแถว และแถว “เงื่อนไขเท็จ → หยุด”
7. **Why it teaches:** “ไม่รวมค่าสุดท้าย” และ “ตัวสะสมต้องอยู่นอกลูป” กลายเป็นสิ่งที่นับได้จากตาราง
8. **Beginner scaffold:** ลูป 3 รอบ ตัวแปรเดียว
9. **Support removal:** เดินทีละรอบ → ข้ามไปดูท้ายตาราง → ทายจำนวนรอบก่อน → อ่านโค้ดใหม่แล้วบอกผล
10. **Failure experience:** ตัวสะสมในลูป → ตารางแสดง total = i ทุกแถว; while ไม่หยุด → ตารางหยุดที่ 20 แถวพร้อมป้าย “เงื่อนไขไม่เคยเป็นเท็จ”
11. **Feedback:** “range(1, 5) หยุดก่อน 5 — ตารางมี 4 แถว”
12. **Challenge / fun:** ทายจำนวนแถวก่อนรัน · *Fun without rewards:* **ใช่** — การเห็นตารางเติมตามคาดน่าพอใจ
13. **Independent application:** นับตัว a ใน "banana"; คูณ 2 จนเกิน 100
14. **Proof of understanding:** บอกจำนวนรอบและค่าสุดท้ายของลูปใหม่ก่อนรัน
15. **Evidence:** responses (ทายรอบ/ผล), attempts/solved, debug, hint
16. **Game decision:** OPTIONAL_GAME
17. **Game reason:** “สั่งหุ่นเดิน/วางบล็อกซ้ำด้วยลูป” — จำนวนรอบเห็นเป็นการกระทำ ถ้าเกมใช้ trace จริง; ไม่จำเป็นต่อบทหลัก
18. **Current implementation:** KEEP_BUT_IMPROVE — loop trace ดี ขาด what-if ขอบเขตและการย้ายตัวสะสมด้วยมือ
19. **Priority:** P1
20. **Acceptance test:** ผู้เรียนบอกได้ก่อนรันว่า `for i in range(2, 6)` ทำงานกี่รอบ และอธิบายว่าทำไม total = 0 ต้องอยู่นอกลูป

### prog-fn-functions
**SUBJECT:** programming · **TOPIC:** prog-functions · **SKILLS:** skill-prog-functions, skill-prog-collections

1. **Core understanding:** ฟังก์ชันรับค่าเข้า ทำงาน แล้ว **ส่งค่ากลับ** ไปยังจุดที่เรียก; print แค่แสดง; list ใช้ index เริ่ม 0; dict ค้นด้วย key
2. **Why it is hard:** return กับ print ดูเหมือนกันในผลลัพธ์; การกระโดดเข้า–ออกฟังก์ชันมองไม่เห็น; index 0 ขัดสัญชาตญาณ

4. **Learner action:** เดิน trace (มีอยู่); เปรียบเทียบฟังก์ชันคู่ (return vs print) โดยใช้ผลในการคำนวณต่อ; แตะช่อง list ตาม index
5. **Immediate consequence:** ที่จุดเรียก `area(3, 4) * 2` นิพจน์ถูกแทนด้วย `12 * 2`; เวอร์ชัน print ได้ `None * 2` → TypeError จริง
6. **Best mechanic:** *Return เป็นค่าที่กลับมาแทนที่* — แสดงบรรทัดเรียกพร้อม “ช่องว่างรอค่า”; เมื่อฟังก์ชัน return ค่าลอยกลับไปเติมช่องนั้น; เวอร์ชัน print เติมช่องด้วย `None` และผลลัพธ์ที่พิมพ์ออกไปอยู่ในคอนโซลแยก; ช่วง collections: แถว list มีหมายเลข 0,1,2 ใต้ช่อง ผู้เรียนแตะเพื่ออ่าน `scores[1]`; dict เป็นลิ้นชักติดป้าย key
7. **Why it teaches:** ความต่างของ return/print กลายเป็นสิ่งที่เห็น: ค่ากลับมาที่บรรทัด vs ไปที่หน้าจอ
8. **Beginner scaffold:** ฟังก์ชันหนึ่งบรรทัด เรียกครั้งเดียว
9. **Support removal:** trace → ทายค่าที่จะเติมช่องก่อน → ฟังก์ชันใช้ list → อ่านโค้ดใหม่แล้วบอกผล
10. **Failure experience:** ใช้ print แทน return → ช่องเติม `None` และบรรทัดถัดไปล้ม; อ่าน `scores[3]` จาก 3 ตัว → IndexError ชี้ช่องที่ไม่มี
11. **Feedback:** “ฟังก์ชันนี้แสดงค่า แต่ไม่ได้ส่งค่ากลับ — จุดที่เรียกจึงได้ None”
12. **Challenge / fun:** ทายว่าช่องจะได้ค่าอะไร · *Fun without rewards:* **ใช่**
13. **Independent application:** สองโจทย์อ่านโค้ด (python3-verified) ที่ผสม function + dict
14. **Proof of understanding:** อธิบาย (เลือก) ว่าทำไม `x = show(5)` ได้ None และแก้ให้ใช้ได้
15. **Evidence:** responses, attempts/solved, debug, hint
16. **Game decision:** NO_GAME_NEEDED
17. **Game reason:** แนวคิดเรื่องการไหลของค่าสอนตรงกว่าในภาพ trace
18. **Current implementation:** KEEP_BUT_IMPROVE — call trace + dict trace ดี ขาดการเทียบ return vs print ที่จุดเรียก (จุดพลาดอันดับหนึ่ง)
19. **Priority:** P1
20. **Acceptance test:** ผู้เรียนทายได้ว่า `def f(): print(3)` แล้ว `y = f() + 1` จะเกิด error เพราะ f() ได้ None
- **Mobile:** 390 บรรทัดเรียกติดด้านบน (sticky) เห็นช่องรอค่าขณะเดินในฟังก์ชัน · 768/1440 โค้ด | หน่วยความจำ/คอนโซล

### phy-vec-units
**SUBJECT:** physics · **TOPIC:** phy-units-vectors · **SKILLS:** skill-phy-units

1. **Core understanding:** การแปลงหน่วยคือการคูณด้วย “1” ในรูปตัวประกอบ (1000 m / 1 km) ที่ทำให้หน่วยเดิมตัดกัน; ทิศของตัวประกอบกำหนดว่าตัวเลขโตหรือเล็ก

3. **Make visible:** หน่วยที่ตัดกัน (cancellation) และขนาดของตัวเลขที่ต้องสมเหตุสมผล
4. **Learner action:** ลากกระเบื้องตัวประกอบลงสมการ **และพลิกบน/ล่าง** เอง
5. **Immediate consequence:** หน่วยที่บน/ล่างตรงกันขีดฆ่าทันที; ถ้าพลิกผิด หน่วยกลายเป็น `km²/m` แทนที่จะหายไป และตัวเลขกระโดดไปผิดทาง
6. **Best mechanic:** *กระเบื้องตัดหน่วย* — `72 km/h` อยู่ทางซ้าย; ผู้เรียนเลือกกระเบื้อง “km ↔ m” และ “h ↔ s” จากถาด วางลงแล้วแตะเพื่อพลิก; หน่วยที่ตัดกันมีเส้นขีดฆ่า ผลตัวเลขอัปเดตทุกครั้ง; ทายก่อนว่าคำตอบควร “มากหรือน้อยกว่า 72” (มีอยู่ในรูปทาย)

8. **Beginner scaffold:** แปลงหน่วยเดียว (kg → g) กระเบื้องเดียว
9. **Support removal:** หนึ่งกระเบื้อง → สองกระเบื้อง (km/h → m/s) → คำนำหน้าหน่วย μ, M → ผู้เรียนเขียนตัวประกอบเองโดยไม่มีถาด
10. **Failure experience:** พลิกผิด → หน่วยไม่ตัด เห็น `km·km/(m·h)` และตัวเลข 259.2 พร้อมป้าย “รถเดินเร็วกว่าเสียง?”
11. **Feedback:** “km ยังอยู่ทั้งบนและล่างไม่ตรงกัน — พลิกกระเบื้องให้ km อยู่ตรงข้ามกับ km เดิม”
12. **Challenge / fun:** ทำให้หน่วยหายหมดเหลือแค่หน่วยที่ต้องการด้วยกระเบื้องน้อยที่สุด · *Fun without rewards:* **ใช่** — การขีดฆ่าหน่วยจนเหลือหน่วยเป้าหมายน่าพอใจเหมือนต่อจิ๊กซอว์
13. **Independent application:** 1.2 km/min → m/s; 900 m/min → km/h
14. **Proof of understanding:** ทายถูกว่าตัวเลขจะโตหรือเล็กก่อนคำนวณ และวางตัวประกอบให้หน่วยตัดได้ในโจทย์ใหม่
15. **Evidence:** responses (ทาย), จำนวนครั้งที่พลิกผิด, attempts/solved, hint, reveal
16. **Game decision:** NO_GAME_NEEDED
17. **Game reason:** กระเบื้องตัดหน่วยเป็นปริศนาในตัว บทสั้น
18. **Current implementation:** REDESIGN — unit-ladder เป็นการกด “ขั้นต่อไป” ดูการแปลงที่เขียนไว้แล้ว (passive) ผู้เรียนไม่เคยเลือกทิศตัวประกอบ ซึ่งคือจุดพลาดอันดับหนึ่ง
19. **Priority:** P0
20. **Acceptance test:** ผู้เรียนแปลง 54 km/h เป็น m/s ได้ถูกโดยวางตัวประกอบเอง และอธิบายได้ว่าทำไมไม่คูณ 3.6
- **Mobile:** 390 ถาดกระเบื้องเป็นแถบเลื่อนล่าง แตะเพื่อวาง/พลิก · 768/1440 ถาด | สมการ

2. **Why it is hard:** บวกขนาดตรง ๆ (3 + 4 = 7); สลับ sin/cos; ไม่เห็นว่าการกระจัดคือเส้นตรงจากต้นถึงปลาย
3. **Make visible:** การเคลื่อนที่เป็นลูกศรต่อกัน (path vs displacement) และเงาของเวกเตอร์บนแกน
4. **Learner action:** ลากลูกศรต่อหัวต่อหาง; หมุนลูกศรด้วยมุม; ดูเงาบนแกน
5. **Immediate consequence:** เส้นการกระจัดลัพธ์ (ตรงจากต้นถึงปลาย) ปรากฏพร้อมความยาว 5 เทียบระยะทางเดินรวม 7; เงา x/y ยาว/สั้นตามมุม
6. **Best mechanic:** *เดินด้วยลูกศร* — ผู้เรียนพาตัวละครเดิน 3 m ตะวันออก (ลากลูกศร) แล้ว 4 m เหนือ ต่อหัวต่อหาง; ระบบวาดลูกศรลัพธ์และวัดทั้ง “ระยะที่เดิน 7 m” กับ “การกระจัด 5 m”; ช่วงสอง หมุนแรง 10 N ที่ 30° ดูเงาบนพื้น (Fₓ) ยาวกว่าเงาแนวดิ่ง (ใช้ explorer เดิม แต่ **เปิดให้สำรวจก่อนทาย**)
7. **Why it teaches:** 3 + 4 ≠ 7 กลายเป็นสิ่งที่วัดได้บนจอ; cos คือ “เงาบนพื้น” ที่เห็น
8. **Beginner scaffold:** ลูกศรตั้งฉากบนตารางจำนวนเต็ม
9. **Support removal:** ตั้งฉาก → มุมใด ๆ → ทายองค์ประกอบก่อนหมุน → คำนวณเองโดยไม่มีรูป
10. **Failure experience:** ตอบ 7 m → ระบบวางเส้น 7 m จากจุดเริ่ม ซึ่งยื่นเลยจุดปลายไปให้เห็น
11. **Feedback:** “7 m คือระยะทางที่เดิน — การกระจัดคือเส้นตรงจากจุดเริ่มถึงจุดจบ”
12. **Challenge / fun:** พาตัวละครไปถึงธงด้วยลูกศรตามเงื่อนไข · *Fun without rewards:* **ใช่**
13. **Independent application:** A = 4 แกน x, B = 3 แกน y → ขนาดและ tan มุม; ลากกล่องด้วย 100 N ที่ 60°
14. **Proof of understanding:** แยก “ระยะทาง vs การกระจัด” ในสถานการณ์ใหม่ และเลือก cos/sin ถูกจากรูป
15. **Evidence:** responses, attempts/solved, hint, reveal
16. **Game decision:** NO_GAME_NEEDED
17. **Game reason:** การเดินด้วยลูกศรเป็นกิจกรรมสั้นที่พอใจในตัว
18. **Current implementation:** KEEP_BUT_IMPROVE — explorer ดีแต่ล็อกไว้หลังการพิมพ์คำตอบ (คำนวณก่อนเห็น) และไม่มีการรวมหัวต่อหาง/ระยะทาง vs การกระจัด
19. **Priority:** P1
20. **Acceptance test:** ผู้เรียนบอกได้ว่าเดิน 6 m ไปแล้ว 8 m ตั้งฉากกัน การกระจัดคือ 10 m ไม่ใช่ 14 m และอธิบายจากภาพ

### phy-kin-1d
**SUBJECT:** physics · **TOPIC:** phy-kinematics · **SKILLS:** skill-phy-kinematics-equations, skill-math-graph-reading

1. **Core understanding:** ความเร่งคงตัวคือความเร็วเปลี่ยนเท่ากันทุกวินาที → ระยะในแต่ละวินาทียาวขึ้นเรื่อย ๆ; กราฟ v–t ความชัน = a พื้นที่ = s; เลือกสมการจากสิ่งที่รู้/ไม่รู้; เบรกคือ a ติดลบ
2. **Why it is hard:** สมการ 3 ตัวถูกท่องโดยไม่รู้ว่าใช้ตอนไหน; ไม่เคยเห็นการเคลื่อนที่จริงคู่กับกราฟ
3. **Make visible:** การเคลื่อนที่ตามเวลา (movement + timing) — ตำแหน่งที่แต่ละวินาที และกราฟที่วาดพร้อมกัน
4. **Learner action:** ตั้ง u, a แล้วกด RUN; หยุดดูทีละวินาที; ทายตำแหน่งวินาทีถัดไปก่อน; เลือกสมการด้วยการแตะ “สิ่งที่รู้”
5. **Immediate consequence:** รถวิ่งบนราง ทิ้ง “รอยเท้า” ทุก 1 วินาทีที่ห่างขึ้นเรื่อย ๆ; กราฟ v–t วาดตามจริงขณะวิ่ง; เบรก → รอยเท้าถี่ขึ้นจนหยุด
6. **Best mechanic:** *รางวิ่ง + รอยทุกวินาที + กราฟซิงก์* — ผู้เรียนทายว่ารอยวินาทีที่ 3 จะอยู่ไหน (วางหมุดบนราง) → RUN → เทียบหมุดกับรอยจริง; กราฟ v–t วาดคู่กันแบบเรียลไทม์ แตะพื้นที่ใต้กราฟแล้วตัวเลขระยะบนรางไฮไลต์; ช่วงสุดท้ายเป็น *การ์ดตัวแปร*: ผู้เรียนพลิกการ์ด u, v, a, s, t ที่โจทย์ให้ แล้วสมการที่ใช้ได้สว่างขึ้นเอง
7. **Why it teaches:** “ระยะเพิ่มขึ้นเพราะความเร็วเพิ่ม” เห็นจากระยะห่างรอยเท้า; ความเชื่อมกราฟ ↔ การเคลื่อนที่เกิดจากการวาดพร้อมกัน; การเลือกสมการกลายเป็นตรรกะ “สมการไหนมีแต่ตัวที่รู้ + ตัวที่ถาม”
8. **Beginner scaffold:** เริ่มจากหยุดนิ่ง a เป็นบวก จำนวนเต็ม
9. **Support removal:** RUN ดู → ทายก่อน RUN → เบรก (a ลบ) → การ์ดตัวแปรแบบนำทาง → เลือกสมการเองแล้วคำนวณ
10. **Failure experience:** ทายรอยห่างเท่ากัน → รอยจริงห่างขึ้นเรื่อย ๆ ข้างหมุดของผู้เรียน; ลืมเครื่องหมายลบตอนเบรก → รถเร่งขึ้นแทนที่จะหยุด
11. **Feedback:** “รถเร่งขึ้นแทนที่จะเบรก — ตอนเบรก a ต้องมีทิศตรงข้ามกับความเร็ว (ติดลบ)”
12. **Challenge / fun:** หยุดรถให้ตรงเส้นด้วยการเลือกความหน่วง · *Fun without rewards:* **ใช่** — การหยุดตรงเส้นพอดีเป็นความพอใจจริง
13. **Independent application:** กราฟ v–t (0,0)→(4,8) หาความเร่งและการกระจัด; จากหยุดนิ่ง a = 2 ต้องใช้เวลากี่วินาทีไป 64 m
14. **Proof of understanding:** ทายรูปแบบรอยเท้าของการเบรกได้ และเลือกสมการถูกจากชุดตัวแปรใหม่
15. **Evidence:** responses (หมุดทาย, การ์ดที่เลือก), attempts/solved, hint, reveal
16. **Game decision:** NO_GAME_NEEDED
17. **Game reason:** “หยุดรถตรงเส้น” เป็นความท้าทายในบทอยู่แล้ว ไม่ต้องแยกเป็นเกม
18. **Current implementation:** REDESIGN — มีกราฟ v–t ที่ปรับค่าได้ แต่ไม่มีวัตถุเคลื่อนที่, การสำรวจล็อกหลังพิมพ์ตัวเลข และการเลือกสมการยังเป็นข้อความ
19. **Priority:** P0
20. **Acceptance test:** ผู้เรียนทายได้ก่อน RUN ว่ารอยวินาทีถัดไปจะห่างกว่ารอยก่อน และเลือกสมการที่ถูกเมื่อไม่รู้เวลา
- **Mobile:** 390 รางแนวนอนเต็มกว้าง กราฟใต้ราง ปุ่ม RUN ใหญ่ · 768 ราง + กราฟซ้อน · 1440 ราง | กราฟ | การ์ด
- **A11y:** RUN/หยุด/วินาทีถัดไปด้วยคีย์บอร์ด; ตำแหน่งทุกวินาทีเป็นตารางข้อความ; ลดการเคลื่อนไหว = แสดงรอยทั้งหมดทันทีโดยไม่วิ่ง

### phy-dyn-newton
**SUBJECT:** physics · **TOPIC:** phy-dynamics · **SKILLS:** skill-phy-free-body, skill-phy-newton-second

1. **Core understanding:** ความเร่งมาจาก **แรงลัพธ์** และแปรผกผันกับมวล; ต้องระบุแรงทุกแรงบนวัตถุ (แผนภาพแรง) ก่อนคำนวณ
2. **Why it is hard:** ใช้แรงตัวเดียวแทนแรงลัพธ์; สับสนมวลกับน้ำหนัก; ใส่ “แรงของการเคลื่อนที่” ที่ไม่มีจริง
3. **Make visible:** ความเป็นเหตุผล F, m → a (มีแล้ว) และ **แรงที่มองไม่เห็นบนวัตถุ** (น้ำหนัก แรงตั้งฉาก แรงเสียดทาน)
4. **Learner action:** ทาย → เปลี่ยน F หรือ m → ปล่อยรถ → ดูตาราง (มีอยู่); **ลากลูกศรแรงไปติดกล่อง** ในสถานการณ์
5. **Immediate consequence:** รถเร่ง/ช้าตามค่า; บนกล่อง ลูกศรรวมเป็นลูกศรแรงลัพธ์ และกล่องเร่งตามลูกศรลัพธ์ทันที
6. **Best mechanic:** *การทดลองยุติธรรม + ตัวสร้างแผนภาพแรง* — ช่วงหนึ่ง cart-lab (มีอยู่: เปลี่ยนทีละตัวแปร มีตารางวัด); ช่วงสอง กล่องบนพื้นมีแรงเสียดทาน: ผู้เรียนเลือกแรงจากถาด (น้ำหนัก, แรงตั้งฉาก, แรงดึง, แรงเสียดทาน, *“แรงไปข้างหน้า”* เป็นตัวหลอก) ลากไปติดกล่องพร้อมทิศ; ระบบรวมเป็นแรงลัพธ์และปล่อยกล่องตามนั้น
7. **Why it teaches:** “แรงลัพธ์” คือผลรวมของลูกศรที่ผู้เรียนวางเอง; ใส่แรงผิดแล้วกล่องเคลื่อนผิดจากที่ควรเป็น
8. **Beginner scaffold:** พื้นลื่น แรงเดียว
9. **Support removal:** หนึ่งแรง → แรงสวนทาง (แรงเสียดทาน) → แรงแนวดิ่งหักล้างกัน → คำนวณ a เองจากแผนภาพที่สร้าง
10. **Failure experience:** วาง “แรงไปข้างหน้า” → กล่องเร่งเกินจริงและป้ายถาม “อะไรออกแรงนี้?”; ลืมแรงเสียดทาน → กล่องเร็วกว่าการวัดจริงในตาราง
11. **Feedback:** “ทุกแรงต้องมีผู้ออกแรง — ‘แรงไปข้างหน้า’ ไม่มีผู้ออกแรง ลบออก”
12. **Challenge / fun:** หาแรงดึงพอดีให้กล่องเร่ง 2 m/s² · *Fun without rewards:* **ใช่** — การทดลองแล้วตัวเลขตรงทฤษฎีน่าพอใจ
13. **Independent application:** กล่อง 4 kg μ = 0.25 ดึง 20 N; รถ 1,200 kg เร่ง 2.5 m/s²
14. **Proof of understanding:** สร้างแผนภาพแรงถูกในสถานการณ์ใหม่ และทายทิศการเร่งจากแผนภาพก่อนปล่อย
15. **Evidence:** responses (ทาย), attempts/solved, แรงที่วางผิด, hint, reveal
16. **Game decision:** OPTIONAL_GAME
17. **Game reason:** “ส่งกล่องให้ถึงเป้าภายในเวลา” — การเลือกแรง/มวลคือการเรียน; ไม่จำเป็นต่อบทหลัก
18. **Current implementation:** KEEP_BUT_IMPROVE — cart-lab ดีมาก (อ้างอิงได้) แต่ทักษะแผนภาพแรงเป็นแค่ภาพอธิบาย ผู้เรียนไม่ได้สร้างเอง
19. **Priority:** P1
20. **Acceptance test:** ผู้เรียนวางแรงครบและไม่ใส่แรงสมมติบนกล่องที่ถูกลากบนพื้นมีแรงเสียดทาน แล้วทายทิศความเร่งถูก
- **Mobile:** 390 กล่อง + ถาดแรงด้านล่าง (แตะเลือก แตะทิศ) · 768/1440 ฉาก | ถาด | ตารางวัด
- **A11y:** วางแรงด้วยปุ่ม “เพิ่มแรง… ทิศ…”; ผลรวมแรงเป็นข้อความ; ลดการเคลื่อนไหว = แสดงตำแหน่งสุดท้าย

7. **Why it teaches:** ลำดับหัวข้อเป็นโครงที่เห็นได้ ไม่ใช่ขนาด
8. **Beginner scaffold:** บล็อกหัวข้อพร้อมใช้
9. **Support removal:** บล็อก → เติมแท็กปิด → แก้การซ้อน → เขียนส่วนแนะนำเอง
10. **Failure experience:** ปิดไม่ครบ → ย่อหน้ากลายเป็นตัวใหญ่ (มีอยู่); ข้ามระดับ → สารบัญมีขั้นหาย
11. **Feedback:** “`<strong>` เปิดอยู่ข้างใน `<p>` จึงต้องปิด `</strong>` ก่อน `</p>`”
12. **Challenge / fun:** ซ่อมหน้าที่เพี้ยน · *Fun without rewards:* **ใช่**
13. **Independent application:** ส่วนแนะนำตัว: h1, h2, p×2, strong
14. **Proof of understanding:** หาแท็กที่ยังไม่ปิดในโค้ดใหม่ได้
15. **Evidence:** attempts/solved/hint/reveal (มีอยู่)
16. **Game decision:** OPTIONAL_GAME
17. **Game reason:** “จับคู่แท็ก” — การปิดแท็กให้ถูกคู่คือทักษะ nesting (ตาม v1)
18. **Current implementation:** KEEP_BUT_IMPROVE (เล็ก) — ขาดภาพลำดับชั้นของหัวข้อ
19. **Priority:** P2
20. **Acceptance test:** ผู้เรียนเห็นโค้ดใหม่ที่มี `<h1>` ไม่ปิดแล้วทายได้ว่าย่อหน้าถัดไปจะแสดงผิดอย่างไร
- **Mobile:** ตรวจแล้ว · สารบัญใหม่วางใต้หน้าเว็บที่ 390 · **A11y:** สารบัญเป็นรายการซ้อน `<ul>` อ่านได้

### web-html-links-images
**SUBJECT:** web · **TOPIC:** web-html · **SKILLS:** skill-web-html-attributes, skill-web-html-links-images

1. **Core understanding:** attribute = ข้อมูลในแท็กเปิดที่เปลี่ยนพฤติกรรม (src รูปไหน, href ไปไหน, alt คำอธิบาย)
2. **Why it is hard:** attribute ไม่แสดงเป็นข้อความจึงดูไร้ผล; alt มองไม่เห็นสำหรับคนตาดี
3. **Make visible:** เหตุ–ผลของค่า (เปลี่ยนค่า → รูป/ปลายทางเปลี่ยน) และ alt เมื่อรูปโหลดไม่ได้
4. **Learner action:** เปลี่ยนค่าในแผง attribute หรือในโค้ด, กดลิงก์ดูปลายทาง, ทำให้รูปหาย
5. **Immediate consequence:** รูปเปลี่ยน, alt โผล่แทนรูปที่หาย, ป้ายปลายทางลิงก์
6. **Best mechanic:** *Attribute Knobs* (มีอยู่) — ไม่เปลี่ยน
7. **Why it teaches:** ค่าที่มองไม่เห็นทำให้สิ่งที่มองเห็นเปลี่ยน
8. **Beginner scaffold:** เปลี่ยนค่าเดียวจากตัวเลือก
9. **Support removal:** ตัวเลือก → พิมพ์ค่า → สร้างรูป+ลิงก์เอง
10. **Failure experience:** ไม่มี alt → ป้าย “⚠ รูปนี้ยังไม่มี alt”; รูปหายโดยไม่มี alt → “รูปแสดงไม่ได้ และไม่มีคำอธิบาย”
11. **Feedback:** “รูปนี้ยังไม่มี alt ซึ่งช่วยอธิบายรูปเมื่อมองไม่เห็นภาพ”
12. **Challenge / fun:** ทำให้หน้าเว็บ “อ่านได้แม้ไม่มีรูป” · *Fun without rewards:* **ใช่**
13. **Independent application:** รูป + ข้อความ + ลิงก์ที่ข้อความบอกปลายทาง
14. **Proof of understanding:** แก้ลิงก์ “คลิกที่นี่” และรูปที่ไม่มี alt ในหน้าใหม่
15. **Evidence:** attempts/solved/hint/reveal (มีอยู่)
16. **Game decision:** NO_GAME_NEEDED
17. **Game reason:** แผงปรับค่าให้ผลทันทีเพียงพอ
18. **Current implementation:** GOOD_AS_IS (รอการ playtest ของผู้ใช้)
19. **Priority:** P2
20. **Acceptance test:** ผู้เรียนอธิบายได้ว่า alt ใช้เมื่อไรโดยอ้างสิ่งที่เห็นเมื่อรูปหาย
- **Mobile/A11y:** ตรวจแล้ว; ช่องปรับค่าไม่ล้น (แก้แล้ว)

### web-html-page-structure
**SUBJECT:** web · **TOPIC:** web-html · **SKILLS:** skill-web-html-page-structure

1. **Core understanding:** โค้ดซ้อนเป็นชั้น = พื้นที่ซ้อนบนหน้า; head ไม่แสดง body แสดง; header/main/section/footer มีความหมาย
2. **Why it is hard:** head กับ header ชื่อคล้าย; การซ้อนเป็นนามธรรมในโค้ดยาว
3. **Make visible:** โครงสร้าง (structure) — พื้นที่บนหน้าที่ตรงกับแท็ก
4. **Learner action:** แตะแท็ก ↔ พื้นที่, ย้ายบรรทัดเข้าพื้นที่, ห่อด้วยโครงเอกสาร
5. **Immediate consequence:** พื้นที่ไฮไลต์, ชื่อแท็บเปลี่ยนจาก `<title>`
6. **Best mechanic:** *Region Mapping* (มีอยู่) **+ ปรับ:** ที่ 390 แผนผังโค้ดซ้ำกับช่องแก้โค้ด ทำให้ยาวมาก — เสนอให้แผนผังเป็นโหมดสลับ (แก้โค้ด | มองโครง) แทนแสดงสองอัน; ขั้นจัดพื้นที่ให้ “ลากบรรทัดเข้ากรอบพื้นที่” บนหน้าเว็บได้ (นอกจากแก้โค้ด)
7. **Why it teaches:** ผู้เรียนเห็นว่าแท็กที่ซ้อนกันคือกรอบที่ซ้อนกัน
8. **Beginner scaffold:** โค้ดที่มีพื้นที่ครบ แตะสำรวจก่อน
9. **Support removal:** สำรวจ → ย้ายบรรทัดเดียว → ห่อโครงเอกสาร → จัดหน้าทั้งหน้า
10. **Failure experience:** เนื้อหาหลักใน footer → กรอบ footer ไฮไลต์และถาม; title ไม่อยู่ใน head → ข้อความบอกให้ย้าย (แก้แล้ว)
11. **Feedback:** “`<h1>` ยังอยู่นอก `<body>` — ย้ายเข้าไประหว่าง `<body>` กับ `</body>`”
12. **Challenge / fun:** จัดหน้าที่กระจัดกระจายให้เป็นระเบียบ · *Fun without rewards:* **ใช่** (แต่ช่วงห่อโครงเอกสารเป็นงานพิมพ์ — ต้องลดภาระ)
13. **Independent application:** หน้า header/main(section)/footer
14. **Proof of understanding:** แยก head กับ header ได้ในโค้ดใหม่
15. **Evidence:** attempts/solved/hint/reveal (มีอยู่)
16. **Game decision:** NO_GAME_NEEDED
17. **Game reason:** การจัดพื้นที่สั้นและตรง
18. **Current implementation:** KEEP_BUT_IMPROVE — ภาระพิมพ์และความยาวบนมือถือ
19. **Priority:** P2
20. **Acceptance test:** บนมือถือ ผู้เรียนย้ายบรรทัดลิขสิทธิ์เข้า footer ได้โดยไม่ต้องเลื่อนหน้ายาวไปมา
- **Mobile:** ไม่ล้นที่ 390 แต่ยาว → ใช้โหมดสลับ · **A11y:** ลากบรรทัดเข้ากรอบต้องมีปุ่ม “ย้ายเข้า…” สำรอง
